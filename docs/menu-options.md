# 텍스트 세부 선택

온도·소스·음료 종류·맛을 같은 기능으로 관리한다. 관리자 메뉴 등록·수정 화면의 ‘세부 선택 추가’에서 이름, 쉼표로 구분한 항목, 선택 개수를 입력한다. 추가 금액은 없으며 메뉴 판매 가격을 그대로 사용한다.

| 메뉴 또는 구성품 | 선택 이름 | 입력 항목 | 선택 개수 |
| --- | --- | --- | --- |
| 아메리카노 | 온도 | 아이스, 핫 | 1 |
| 리코타 치즈 샐러드 | 소스 | 유자, 발사믹 | 1 |
| 탄산음료 구성품 | 종류 | 콜라, 사이다 | 1 |
| 붕어빵 2개 일반 메뉴 | 맛 | 팥, 슈, 피자 | 2 |

세트의 선택은 **구성품에 등록**한다. 탄산음료 구성품의 선택 개수가 1이고 ‘탄산음료 2잔’ 세트에 구성 수량이 2이면 주문 시 두 잔을 각각 선택한다. 같은 종류 두 잔도 가능하다. 필라프 세트에 같은 구성품을 1개 넣으면 한 잔만 선택한다. 새 음료 종류는 해당 구성품의 항목에 텍스트를 추가하면 된다.

붕어빵을 낱개 단위로 조리·서빙 완료 처리하려면 ‘붕어빵’을 구성 전용으로 만들고 맛 선택 개수 1, ‘붕어빵 2개’ 세트의 구성 수량 2로 등록한다. 일반 메뉴에 선택 개수 2를 지정하면 조리·서빙 횟수는 판매 묶음 수 기준이다.

직원은 메뉴를 누른 뒤 선택 팝업에서 고른다. 선택이 다르면 장바구니에서 별도 행으로 표시되고, 같은 선택은 수량으로 합쳐진다. 한 행에서 수량을 늘리면 동일한 선택을 반복 주문하는 의미다. 선택이 없는 메뉴는 바로 장바구니에 들어간다.

선택 결과는 해당 구성품의 주방·서빙 작업 이름에 표시된다. CSV 마지막 열 ‘세부 선택(1개 기준)’에도 기록되며 메뉴별 주문금액은 변하지 않는다. 세트 음료의 선택은 음료 작업에만 붙고 다른 구성품 작업에는 붙지 않는다. 구성 수량·판매 수량과 함께 읽어야 한다.

선택 항목을 없애려면 관리자에서 그 텍스트를 제거한다. 기존 주문의 선택 이력은 보존된다. 열어 둔 장바구니가 변경된 선택 설정을 사용하면 ‘선택 변경’으로 접수를 막으므로 해당 항목을 빼고 다시 선택한다. 옵션 자체의 추가금·별도 재고 수량·전용 품절 토글은 이번 범위에 포함하지 않는다.

## 적용

`20261102_set_menus.sql` 이후 `migrations/20261103_menu_options.sql`을 실행하고 앱을 업데이트한다. 직원 화면은 새로고침한다. 기존 메뉴의 세부 선택 기본값은 빈 목록이므로 기존 판매·금액·주문은 유지된다. 미확인 주문을 먼저 해소하고 업데이트한다.

자동 리허설 스크립트는 세트와 텍스트 옵션도 포함한다. 실제 선택 팝업과 알림음은 앱에서 별도로 확인한다. 개발용 SQL 검증은 `tests/menu-options.sql`에서 수행한다. 운영 DB와 실제 메뉴는 자동으로 변경하지 않는다.
