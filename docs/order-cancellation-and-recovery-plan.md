# 주문 취소·실수 복구 기획서

상태: 보류 — 사용자 요청으로 취소·복구 기능을 추가하지 않음. 주문 접수 및 조리·서빙 최종 수량 확인 팝업으로 범위 변경. · 2026-10-30

## 1. 목표와 범위

잘못 받은 주문과 잘못 누른 완료를 기록을 지우지 않고 바로잡는다.
현재의 수량별 조리·서빙 및 매장별 주문번호를 유지한다.

이번 범위는 주문 전체 취소, 취소 복구, 조리·서빙 수량 1개 되돌리기, 완료 주문 다시 열기다.
관리자 화면에 ‘주문 관리’를 추가해 취소와 복구를 한 곳에서 처리한다.
직원 인증·권한 강화, 실제 환불 연동, 메뉴별 부분 취소, 접수 후 메뉴·수량 변경은 이번 범위에서 제외한다.
수량 되돌리기는 처리 기록을 정정하는 기능이며 실제 음식 회수·폐기를 지시하지 않는다.

## 2. 관리자 주문 관리 화면

- 기본 목록은 진행 중인 주문. ‘진행 중 / 완료 / 취소 / 전체’ 필터를 제공한다.
- 주문번호·테이블로 검색하고 최신 주문부터 페이지 단위로 조회한다. 1,000행 제한 때문에 뒷주문이 누락되지 않게 한다.
- 주문 카드를 펼치면 메뉴명, 주문 수량, 조리 수량, 서빙 수량, 당시 가격을 표시한다.
- 카드에는 상태에 맞게 ‘주문 취소’, ‘취소 복구’, ‘완료 되돌리기’를 표시한다.
- 메뉴 행의 ‘수량 정정’에서 ‘서빙 1개 되돌리기’와 ‘조리 1개 되돌리기’를 제공한다.
- 파괴적인 삭제 버튼은 제공하지 않는다. 취소한 주문도 번호와 상세를 보존한다.

## 3. 기능별 동작

| 기능 | 가능한 상태 | 처리 결과 | 화면 안내 |
|---|---|---|---|
| 주문 취소 | 진행 중 또는 완료 | 주문을 취소 상태로 변경. 메뉴·수량·가격은 보존 | 주문번호·테이블과 취소 사유를 확인한 뒤 실행 |
| 취소 복구 | 취소 | 취소 직전 주문 상태로 복구. 조리·서빙 수량 유지 | 복구 후 다시 나타날 작업을 안내 |
| 서빙 1개 되돌리기 | 진행 중, 서빙 수량 > 0 | 서빙 수량만 1 감소 | 조리 수량 유지, 해당 1개가 다시 서빙 대기 |
| 조리 1개 되돌리기 | 진행 중, 조리 수량 > 서빙 수량 | 조리 수량만 1 감소 | 해당 1개가 다시 조리 대기 |
| 완료 되돌리기 | 완료 | 진행 중으로 다시 열기. 수량은 유지 | 서빙 화면에 주문 카드가 다시 나타남 |

### 주문 취소

취소 확인창에 주문번호·테이블·현재 조리/서빙 진행량을 표시한다.
취소 사유는 ‘중복 접수 / 손님 요청 / 주문 입력 실수 / 기타’ 중 하나를 선택한다.
‘기타’일 때만 짧은 사유 입력을 필수로 한다.

조리 또는 서빙을 이미 시작했다면 ‘진행한 작업은 되돌아가지 않습니다. 주방·서빙팀에 취소를 알려주세요’라고 안내한다.
실제 환불이 필요한 경우 별도 처리해야 함을 표시한다. 주문 취소만으로 결제나 환불이 실행되지는 않는다.
완료 주문도 취소할 수 있으며 같은 안내를 적용한다.

취소 즉시 주방·서빙 대기열에서 제외하고 수량 변경·주문 완료를 차단한다.
취소 직전의 주문 상태와 수량을 보존한다. 이미 화면에 떠 있던 직원의 후속 클릭도 DB에서 거절한다.

### 취소 복구

기존 주문번호를 그대로 사용한다. 새 주문을 만들지 않는다.
진행 중이던 주문은 기존 수량부터 이어서 처리한다.
완료 후 취소했던 주문은 완료 상태로 복구한다. 작업을 다시 열려면 별도로 ‘완료 되돌리기’를 사용한다.
메뉴가 현재 품절·숨김·삭제 상태여도 기존 주문 복구는 허용한다. 확인창에는 현재 판매 불가 상태를 표시해 관리자가 실제 준비 가능 여부를 확인하게 한다.

### 수량 정정

‘주문 수량 ≥ 조리 수량 ≥ 서빙 수량 ≥ 0’을 항상 유지한다.
예: 조리 3개·서빙 3개에서 조리 1개를 되돌리려면 먼저 서빙 1개를 되돌려야 한다.
서빙 수량이 조리 수량과 같으면 조리 되돌리기 버튼을 비활성화하고 그 이유를 표시한다.
한 번에 1개만 되돌리며, 메뉴명과 변경 전후 수량을 확인창에 표시한다.
완료·취소 상태에서는 수량 정정을 차단한다. 먼저 완료 되돌리기 또는 취소 복구를 수행한다.

### 완료 되돌리기

전체 수량이 서빙된 상태를 유지하므로 서빙 카드에는 ‘모든 메뉴 서빙 완료’와 ‘주문 완료’가 나타난다.
서빙 자체를 잘못 눌렀다면 관리자가 이어서 ‘서빙 1개 되돌리기’를 실행한다.
조리 기록도 잘못됐다면 그다음 ‘조리 1개 되돌리기’를 실행한다.

## 4. 상태·수량 규칙

주문 전체 상태에는 `cancelled`를 추가한다. 취소 직전 상태는 별도로 보관한다.
진행 중인 주문의 전체 상태는 기존의 `received`를 사용한다. 완료는 `completed`다.
복구 시 기존 `preparing` 상태가 남아 있다면 진행 중 상태로 취급한다.

메뉴 항목의 상태는 저장된 수량에서 계산한다.

| 조건 | 메뉴 상태 |
|---|---|
| 서빙 수량 = 주문 수량 | 서빙 완료 (`served`) |
| 조리 수량 = 주문 수량, 서빙 수량 < 주문 수량 | 조리 완료 (`cooked`) |
| 조리 수량 < 주문 수량 | 조리 중 (`pending`) |

주방은 취소·완료 주문을 제외하고 남은 조리 수량이 있는 항목을 표시한다.
서빙은 취소·완료 주문을 제외하고 기존 주문별 카드를 표시한다.
모든 항목이 서빙 완료된 경우에만 주문 전체 완료를 허용한다. 조건 검사는 DB에서 원자적으로 수행한다.

## 5. 통계·CSV

- 누적 매출, 유효 주문 건수, 조리·서빙 대기 수량에서 취소 주문을 제외한다.
- 주문 건수 카드 이름은 ‘총 주문 건수’에서 ‘유효 주문 건수’로 바꿔 의미를 명확히 한다.
- 취소 복구하면 원래 주문 금액과 현재 대기 수량을 다시 반영한다.
- 수량 정정과 완료 되돌리기는 매출을 바꾸지 않고 대기 현황만 바꾼다.
- CSV에는 취소 주문도 포함한다. 주문번호·메뉴·당시 가격·주문 수량은 보존한다.
- 기존 ‘결제금액’은 ‘주문금액’으로 명확히 표기하고 ‘주문상태’, ‘매출반영금액’, ‘취소사유’, ‘취소시각’을 추가한다.
- 취소 주문의 매출반영금액은 0원, 나머지는 주문금액이다. 원금액과 정산 금액을 구분할 수 있게 한다.
- 기존의 전체 DB 집계, CSV 500행 조회와 작업 중지 권장 안내를 유지한다.

## 6. 동시 작업·통신 오류

취소와 직원의 조리·서빙 클릭이 동시에 발생할 수 있으므로 관련 상태 변경을 모두 DB 함수로 처리한다.
주문 행을 먼저 잠근 뒤 필요한 메뉴 항목을 확인·변경하는 순서를 통일한다.
취소가 먼저 완료되면 이후 직원 클릭은 거절하고 목록을 다시 조회한다.
직원 클릭이 먼저 완료되면 그 수량까지 보존한 상태로 취소한다.

정정 요청에는 고유 요청 ID와 조회 당시의 변경 버전을 포함한다.
같은 요청을 재전송하면 이전 결과를 반환한다. 다른 직원의 변경으로 버전이 달라졌다면 덮어쓰지 않고 재조회한다.
응답 유실 시 결과 확인 전 추가 정정을 막고 같은 요청으로 재시도한다.
성공 또는 재조회 후 관리자·주방·서빙 화면에 변경을 반영한다.
실시간 알림을 놓쳐도 기존의 재접속·화면 복귀·주기적 조회로 복구한다.

## 7. 변경 이력

별도 이력에 주문/메뉴 ID, 작업 종류, 변경 전후 상태·수량, 처리 시각, 요청 ID, 취소 사유를 저장한다.
상태 변경과 이력 저장은 같은 트랜잭션으로 처리한다.
기존에 로그인한 관리자 ID는 기록할 수 있지만 직원 개인 신원 확인은 추가하지 않는다.
화면 역할을 기록하더라도 ‘어느 화면에서 처리했는지’의 참고 정보이며 개인을 인증한 기록으로 표현하지 않는다.
관리자 주문 상세에서 취소·복구·정정 내역을 시간순으로 볼 수 있게 한다.

## 8. 구현 순서와 검증

1. 데이터 보존형 SQL: 취소 상태·변경 버전·이력 및 상태 변경 DB 함수 추가.
2. 기존 조리·서빙·주문 완료 처리를 같은 DB 검증 경로로 연결.
3. 관리자 주문 관리·확인창·수량 정정 UI 구현.
4. 취소 주문의 대기열 제외, 통계·CSV 반영.
5. 임시 DB·다중 화면으로 검증한 뒤 운영 SQL 적용, 배포, 직원 화면 새로고침.

필수 검증 시나리오:

- 접수 직후 취소, 일부 조리·일부 서빙 후 취소, 완료 후 취소.
- 각 취소 상태를 복구했을 때 주문번호·수량·매출이 올바르게 돌아오는지.
- 서빙 정정 후 조리 정정, 0 미만 및 서빙 수량 미만으로 감소시키는 요청 차단.
- 완료 되돌리기 후 서빙 카드 재등장 및 수량 정정.
- 취소와 조리/서빙 클릭, 완료와 수량 정정의 동시 실행.
- 응답 유실·중복 클릭·새로고침 후 같은 요청 재시도.
- 메뉴를 소프트 삭제한 주문의 취소·복구 및 CSV 보존.
- 1,000건 초과 데이터에서 취소 제외 집계와 CSV 매출반영금액 합계 일치.

## 9. 적용 시 주의점

진행 중인 취소는 주방에서 이미 실제 조리를 시작했을 수 있으므로 현장 구두 전달도 병행한다.
새 DB 규칙을 반영한 배포 후에는 모든 직원 화면을 새로고침한다.
기존 주문과 완료 내역은 변경하거나 초기화하지 않고 새 기능부터 기록한다.
운영 DB 적용 전 기획 검토와 테스트를 완료한다. 이 문서는 기능 구현이나 운영 DB 변경을 실행하지 않는다.
