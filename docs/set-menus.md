# 고정 구성 세트 메뉴

판매·결제 내역은 `order_sales`, 실제 조리·서빙 작업은 기존 `order_items`에 저장한다. 세트 구성품의 작업 금액은 0원이며 매출·쿠폰·CSV는 판매 행의 세트 가격으로 계산한다. 기존 주문은 판매 행으로 복사하고 수량·상태·쿠폰 내역은 유지한다.

## 적용

1. 진행 중인 주문 접수를 멈추고, 접수 결과가 불명확한 주문을 먼저 확인한다.
2. 이전 쿠폰·지인 정보·주방 완료 내역 SQL이 적용된 DB에서 `migrations/20261102_set_menus.sql` 전체를 실행한다. 기존 DB에서 초기화용 `database_schema.sql`을 실행하지 않는다.
3. 앱을 업데이트하고 모든 직원 화면을 새로고침한다. 기존 버전의 화면에서는 세트·구성 전용 메뉴를 정상적으로 처리할 수 없다.
4. 아래 예시대로 메뉴를 등록한 후 리허설 매장에서 주문·부분 조리·부분 서빙·CSV를 확인한다.

## 관리자 등록 예시

먼저 ‘세트 구성 전용’으로 아래 두 메뉴를 등록한다. 구성 전용 가격은 0원이며 주문 화면에는 나오지 않는다. 주방 번호는 실제 팀 번호에 맞춘다.

| 구성품 | 담당 주방 |
| --- | --- |
| 필라프 | 필라프팀 구역 |
| 콜라 | 음료팀 구역 |

그다음 ‘세트 메뉴’를 선택하여 판매 메뉴를 등록한다. ‘구성품 추가’에서 **세트 1개 기준** 수량을 입력한다.

| 판매 메뉴 | 가격 | 구성 |
| --- | --- | --- |
| 필라프 세트 | 15,000원 | 필라프 1개 + 콜라 1개 |
| 콜라 2개 | 5,000원 | 콜라 2개 |

사이다 등 다른 종류도 구성 전용 메뉴로 등록하고 ‘필라프+사이다’, ‘콜라+사이다’처럼 고정 구성 판매 메뉴를 만들 수 있다. 일반 메뉴도 구성품으로 쓸 수 있지만, 세트 안에 다른 세트를 넣을 수는 없다. 이번 기능은 주문 중 구성 교체·음료 선택을 제공하지 않는다.

세트 목록의 ‘세트 수정’으로 이름·가격·구성을 바꿀 수 있다. 구성 변경은 새 주문에만 적용되고 과거 판매·작업의 이름과 수량은 바뀌지 않는다. 구성품이 품절·숨김·삭제되면 그 구성품이 들어간 세트도 주문할 수 없다. 화면에서 확인한 구성이 바뀌면 장바구니에서 ‘변경 구성 적용’을 눌러야 하며, DB에서도 접수 시 다시 검사한다.

## 주방·서빙·정산

필라프 세트 2개와 콜라 2개 묶음 1개를 주문하면 35,000원이다. 필라프팀에는 필라프 2개, 음료팀에는 세트 구성 콜라 2개와 묶음 구성 콜라 2개가 별도 작업으로 표시된다. 작업마다 원래 판매 메뉴와 판매 수량이 붙는다. 수량별 조리·부분 서빙 방식은 기존과 같다.

CSV는 판매 메뉴별 행이므로 필라프 세트 2개 30,000원, 콜라 2개 묶음 1개 5,000원으로 내려받는다. 구성품은 별도 매출 행으로 추가하지 않는다. ‘세트 구성(1개 기준)’ 열에 주문 당시 구성을 기록한다. 손님유형 열을 포함한 기존 열 위치는 유지한다. 쿠폰·현금·적립액은 주문의 첫 행에만 표시한다.

기존 API 리허설 스크립트는 7개 구역의 **일반 메뉴**로 동작한다. 세트 등록 후에도 이 스크립트를 사용하려면 각 구역의 일반 메뉴가 필요하다. 세트 조합은 앱에서 별도로 리허설하고, 개발 검증은 `tests/set-menus.sql`과 세트 관련 자동 테스트를 사용한다.

운영 DB에 SQL을 적용하거나 실제 메뉴를 자동 등록하지 않는다. 등록할 음료 종류와 담당 구역 번호는 관리자가 정한다.
